# Обратимая системная политика

`tv_policy.py` — инструмент для ТВ, Python 2.7/3, Linux root. Он **не запускается на ноутбуке для установки**. Для него необходимы `/bin/mount` с bind + readonly remount, `/bin/umount`, `/bin/systemctl`, `/proc`, Python и проверенный Homebrew init.d для persistence. Не устанавливать поверх предыдущей политики. На моделях с другой структурой сначала адаптируй и проверь механизм.

Инструмент намеренно допускает только десять изученных семейств ELF из `privacy.md`, в `/usr/sbin/`, и соответствующие `.service`. Это защита от случайной маскировки общего runtime или критической службы, а не утверждение, что на всех LG есть эти десять файлов. Отсутствующие цели исключи из плана после аудита. Для новых имён/путей нужен обзор и изменение кода; флага обхода нет.

## План и состояния

В отдельном `plan.json`:

```json
{
  "format": 1,
  "identity": {"model": "EXACT_MODEL", "software_version": "EXACT_SOFTWARE_VERSION"},
  "guard_seconds": 180,
  "targets": [{
    "path": "/usr/sbin/contentminer",
    "sha256": "INSERT_ACTUAL_ORIGINAL_ELF_SHA256_FROM_AUDIT",
    "units": ["contentminer.service"],
    "role": "Observed component role on this build",
    "evidence": "Specific audit evidence and registrations",
    "impact": "User-visible functions that may stop"
  }]
}
```

Не переносить пример в рабочий план без точных фактов. Заполнить hashes **исходных** ELF до перекрытия. Значения `identity` — аудиторская привязка, а не автоматическая аттестация модели: перед отправкой плана агент сверяет её с живым ТВ. Список units тоже проверить по `ExecStart` и связям. Выбор пользователя хранится в журнале сеанса, а не bool-поле «approved» внутри скрипта.

Используй новый `STATE=/var/lib/webosbrew/lg-privacy-<session-id>`. Исполняемые файлы и секреты не смешивать; каталогу policy назначается root-only. Команды на ТВ:

```text
python /tmp/tv_policy.py --state STATE init --plan /tmp/plan.json
python STATE/policy.py --state STATE status
python STATE/policy.py --state STATE trial
```

`init` сначала проверяет все выбранные файлы, затем создаёт state/stub/копию policy, ничего не перекрывает. `trial` повторно проверяет hashes всех исходников и чужие mountpoints. Перед изменением запускает независимый rollback guard с handshake готовности. Применяет read-only bind, останавливает только выбранные units и процессы с точным exe. При частичном сбое пытается откатить всю группу. Новый trial при существующем pending не продлевает таймер.

Вернись к обычному экрану. Проверь root-канал, изображение, пульт, Home, нужные приложения/входы, при необходимости периферию. Укладывайся в окно guard, иначе разреши откату сработать и подготовь новый сеанс. После фактического подтверждения работоспособности:

```text
python STATE/policy.py --state STATE confirm
python STATE/policy.py --state STATE persist
```

`persist` допустим после подтверждённого trial; создаёт отдельный `70-lg-privacy-<session-id>` в Homebrew init.d. Он не перезаписывает чужие hooks. Перед reboot нужен рабочий способ вернуться к policy; учитывай порядок старта Homebrew root service и время на физическую проверку. Поставь разумный guard 180–600 секунд заранее, если загрузка/сопряжение медленные. Не менять deadline задним числом вместо проверки.

При первом boot после `persist` guard включается заново. Прочитать `status` и `boot.log`, проверить блокировки и обычные функции, затем `confirm`. Подтверждение trial до reboot не заменяет подтверждение первого boot. После этого последующие boot применяют ту же проверенную политику без ожидания ручного подтверждения каждый раз. Это **не** постоянный watchdog работы экрана. Обновлённый firmware с изменившимися hashes приводит к отказу и выключению этой политики, а не к слепому повторному применению.

## Восстановление

```text
python STATE/policy.py --state STATE rollback
```

Rollback сначала ставит disable marker, снимает только собственные bind mounts (сверяет mountpoint и inode заглушки), проверяет открывшийся оригинал и запускает только те units, которые были active до trial. Чужие mounts не трогает. Ошибки выдаёт отдельно, возвращает ненулевой код; `disabled` не означает, что все unmount прошли успешно. Проверь `last-rollback.json` и состояние ТВ.

Если канал управления потерян во время trial или первого boot — **не отключать питание сразу**, дождаться истечения guard. Таймер — отдельный процесс на ТВ и может восстановить runtime при потере ноутбука/страницы. Он не может спасти ТВ при сбое kernel, питании или повреждении flash. Если guard не восстановил управление, перезапуск убирает runtime bind mounts, однако persistent hook может применить их снова; необходим доступ к writable state, чтобы поставить `disabled.json` или убрать **именно свой** hook, либо проверенный recovery. Не обещать автоматический откат при абсолютно любой неисправности.

После rollback hook остаётся на диске, но пропускается по disable marker. При полном удалении политики сначала убедиться, что все её mounts сняты, затем удалить только её hook и state; архив backup/отчёта сохранить. Изменения согласий, DNS и root удаляются отдельными предусмотренными для них процедурами, этот rollback восстанавливает только системные ELF/units.
